# 起動とイベント運営

## 環境設定

`npm start` は `.env` を任意で読み込みます。Docker Composeは `.env` の値をコンテナへ渡します。実際の秘密値をGitへ登録しないでください。

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| APP_MODE | local | local / public |
| HOST | 127.0.0.1 | Nodeの待受。Compose内は0.0.0.0 |
| PORT | 3000 | Nodeの待受ポート |
| LOCAL_PORT | 3001 | Composeのホスト側ポート。127.0.0.1に限定 |
| MAX_ENVIRONMENTS | 50 | 同時に保持する環境数。1〜1,000 |
| SESSION_TTL_MINUTES | 240 | 無操作時の有効期限。1〜1,440分 |
| SESSION_SECRET | 起動ごとにランダム生成 | publicでは32文字以上の秘密値が必須 |
| BASIC_AUTH_USERNAME | 空 | 入口のBasic認証。passwordと対で設定 |
| BASIC_AUTH_PASSWORD | 空 | SNSアカウントとは別の共有認証情報 |
| TRUST_PROXY | 空 | publicで必須。HTTPSプロキシの実際のIP/CIDRをカンマ区切りで指定 |

シェルから継承した環境変数が `.env` より優先されます。設定不整合の場合は起動を中止します。ローカルでBasic認証を有効にする場合もusername / passwordの両方を設定してください。

## データと期限

参加者ごとのSQLiteとサーバー側セッションは、単一Node.jsプロセスのメモリ上にだけ存在します。同じブラウザのタブはセッションを共有します。Cookieの削除や別ブラウザ利用では別環境になります。

期限切れになるとログイン状態と環境への接続を失い、次回アクセスは初期データの新しい環境になります。処理中の環境は処理完了まで保持し、期限切れの未使用環境を定期回収します。ログイン・ログアウト時にはセッションIDを変更し、環境は維持します。

環境数が上限に達すると、新しい利用者には503を返します。既存利用者は操作を続けられます。期限切れ回収後に新規利用を再開できます。上限の引き上げは使用メモリを確認して判断してください。アカウント処理は同時4件までで、超過時は503を返すため、時間を置いて再試行します。

## 限定公開

公開先にHTTPS終端プロキシを用意し、次を設定します。

- `APP_MODE=public`
- Basic認証のusername / password（SNS用の初期アカウントとは別に設定）
- 32文字以上のランダムな `SESSION_SECRET`
- プロキシの実際の送信元IPまたは必要最小限のCIDRを `TRUST_PROXY` に指定

秘密値の生成例は `node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'` です。生成値は運営者の設定先に保存します。

アプリはTLSを終端しません。プロキシ側でHTTPSを終端し、受信した `X-Forwarded-Proto` をプロキシ自身の正しい値で上書きしてください。アプリの待受に接続できる送信元も実プロキシに限定します。`TRUST_PROXY=true`、ワイルドカード、全IP範囲は使用できません。Dockerではアプリから見えるプロキシの送信元アドレスを確認して設定します。

publicでは、信頼したプロキシ経由のHTTPSと認識できないリクエストは426、Basic認証なし／不正は401になります。全ページ・静的ファイルを対象とし、環境割り当て前に判定します。CookieにはHttpOnly・SameSite=Lax・Secureが付きます。実際の公開URLでログインとCookieが成立することを確認してください。

複数プロセス・複数レプリカや自動スケールには対応しません。運用は1プロセスに固定します。障害によるプロセス再起動でも全データが消えます。

## 再起動と終了

再起動は全参加者の操作・アカウント・投稿・ログインに影響します。運営側で実行タイミングを揃えてください。

- Node: `Ctrl+C` で停止し、`npm start` で起動。
- Compose: `docker compose restart` で初期化、`docker compose down` で終了。
- 公開環境: 採用したホスティングの停止・削除手順を開催前に確認。

公開前には、担当運営者が公開URL、HTTPS、実プロキシ設定、直接アクセス制限、想定人数での性能、終了時の停止・削除を確認します。詳細な未検証項目は[検証記録](verification.md)に記載します。
