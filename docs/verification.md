# 検証記録

2026-09-25、macOS / Node.js v22.22.3で、全利用者が1つのSQLite DBを共有する構成と保存量上限を確認。

| 対象 | 結果 |
| --- | --- |
| `npm test` | 全31テスト成功 |
| `npm run lint` | 成功 |
| DB共有 | 55ブラウザの同時アクセスが成功。初期データは重複せず、セッション期限切れ後も同じDBを使用 |
| アカウント | 別ブラウザから同じアカウントでログイン可能。ユーザー名は全利用者で一意。同時重複登録は一方だけ成功 |
| 投稿と権限 | 公開投稿は別ブラウザのタイムライン・詳細・検索にも表示。非公開投稿の閲覧と編集は所有者だけに許可 |
| セッション | ローテーション、古いCookie、改変Cookie、CSRF、期限切れを確認。Cookie削除や期限切れ後もアカウント・投稿を保持し、再ログインで利用可能 |
| 再起動 | 実子プロセスを停止・再起動し、登録アカウント・投稿・編集・旧Cookieの初期化を確認 |
| 保存件数 | 初期データ・全アカウント・公開／非公開を合算。別ブラウザ、Cookie削除、期限切れ、再ログインでも上限を回避できない |
| 同時登録 | 最後のアカウント枠への同時登録は一方が成功、他方は507。件数は上限以内 |
| SQLite容量 | 8MiBのページ上限を確認。マルチバイト本文で容量に到達すると書き込みに失敗し、失敗した編集は元の行を保持。HTTPでも容量不足の編集は507 |
| 上限到達後 | 保存済みの内容は権限に従って閲覧可能。件数上限でも既存投稿を編集でき、ログインも可能 |
| 検索 | 日本語・引用符・ワイルドカード文字を通常の検索文字として扱い、表示可能な投稿だけを返す |
| 公開モード | Basic認証・必須設定・Secure Cookie・信頼プロキシのHTTP結合テスト成功 |
| `docker compose config --quiet` | 成功 |

作業ツリーの一時コピーでテストとlintを実行した。HTTPテストはローカル待受を許可して実行。共有DBへの変更後の確認は自動テストによるもので、ブラウザでの手動操作は未実施。

保存量上限はSQLiteの挿入トリガーとページ数で制限する。DB容量制限はプロセス全体のRSS上限を保証しない。参加者ごとのアカウント作成数制限、参加コード、IP制限は導入していない。
