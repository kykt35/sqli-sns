# Plan 4: 限定公開の準備・起動手順・総合検証

## 概要

通常SNSの完成形を検証し、Basic認証付きの限定公開に必要な設定と起動手順を用意する。ホスティング先への実デプロイや教材への脆弱性追加は、このPRに含めない。

共通の仕様・入力規則・ルート・対象外は[全体計画](./implementation-overview.md)を参照する。

## 前提条件

- Plan 3までの通常SNSが動作する。
- 公開先、実URL、参加人数は未確定。ローカルで検証できる実装と実環境での確認を区別する。
- Basic認証はSNS認証とは別。全ページ・静的ファイルを保護し、教材DBに認証情報を保存しない。

**特記事項**

- トランクへ機能開発を直接コミットしない。全Taskを同じheadブランチと1つのPRに含める。
- 上位Planのbaseは直下Planのheadとする。下位のマージ後は実際のトランクへ付け替え、差分を再確認する。
- サブタスクを原則1コミットとし、検証だけの作業ではコミットを作らない。テスト→実装→検証の順で進める。
- コードレビューを実施し、指摘を反映してからこのPlanのPRを1つ作成または更新する。リモート未確定ならPR作成は未完了として記録する。
- 計画作成時点では、すべてのTaskは未着手。

## 設計方針

公開モードではBasic認証情報・セッション秘密情報・HTTPSプロキシ設定を必須にし、不足時は起動しない。Basic認証を静的配信と環境割り当ての前に置き、未認証リクエストで環境を消費させない。単一プロセスを起動単位とし、アプリの再起動で全参加者のデータを初期化する。

## タスク一覧

### Task 1: Basic認証と公開モードの設定を実装する

**目的:** イベント用の入口を保護し、設定不足で公開しない起動契約を作る。

**変更ファイル（作成予定）:**

- `src/middleware/basic-auth.js`
- `src/config.js`
- `src/app.js`
- `src/runtime/session-store.js`
- `tests/basic-auth.test.js`
- `tests/public-config.test.js`

**サブタスク:**

1. [ ] **1-1** Basic認証なし／不正／正常の全ルート・静的ファイル、認証前に環境が作られないこと、設定不足、公開Cookie属性、プロキシ由来情報の扱いをテストする。
   - 予定コミット: `test(runtime): define restricted access configuration`
2. [ ] **1-2** Basic認証を全配信の前段に実装し、公開モードの必須設定・Cookie・限定したプロキシ信頼設定を接続する。秘密値をログや応答へ含めない。
   - 予定コミット: `feat(runtime): add basic auth and public mode settings`
3. [ ] **1-3** 公開設定・Basic認証テストと全テスト・lintを実行する。ヘルスチェック等の無認証例外を不用意に追加していないことを確認する。
   - 検証のみ。変更がなければコミット不要。

**受け入れ条件:**

- [ ] 直アクセスでもアプリのBasic認証が機能する。
- [ ] Basic認証は初期データと無関係で、DBの再生成に影響されない。

**サブタスク:**

2. [ ] **2-2** 登録・ログイン・投稿・検索、初期アカウント、再起動時に消える範囲、期限切れ時の挙動、環境上限、Basic認証、停止手順をREADMEと運営文書へ記載する。

## 備考

- Docker内の待受は必要に応じて0.0.0.0とし、ローカルComposeのホスト側ポートは127.0.0.1へ限定する。外部公開では実際のHTTPS終端とネットワーク境界を別途設定する。
- 公開モードのプロキシ信頼設定は実際の構成に限定する。直接リクエストのX-Forwarded-Protoだけを無条件で信用しない。
- 公開前確認が残る場合、PRには「アプリ実装完了、実デプロイ未実施」と記録する。未確定事項を理由にローカルの実装・検証を省略しない。
- 実績は[checklist-4.md](./checklist-4.md)へ記録する。
